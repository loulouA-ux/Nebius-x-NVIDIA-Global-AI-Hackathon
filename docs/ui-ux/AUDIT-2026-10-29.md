# ShipTested UI/UX audit and fixes

This is a local implementation and verification report, not a production release or a security scan. No repository repairs, permission grants, billing actions or real scan submissions were performed.

## Design decisions and sources

- Keep visible action labels alongside recognizable icons. Icons are decorative (`aria-hidden`) when text already supplies the accessible name. Preserve the existing Lucide stroke style rather than introduce a second icon family. [Nielsen Norman Group: Icon usability](https://www.nngroup.com/articles/icon-usability/).
- Buttons and navigation links use their shape, placement, colour and focus state as interactive cues; remove their underlines. Preserve underlines on inline prose links so they remain distinguishable without relying only on colour. [W3C: Designing for accessibility](https://www.w3.org/WAI/tips/designing/), [W3C link styles](https://design-system.w3.org/styles/links.html).
- Preserve ShipTested logos, brand font families, theme tokens, evidence caveats, authentication and explicit repair approval.

| P2 | Text-button and title-button hover styles added underlines | Apply a scoped control rule for buttons, button links and navigation, including hover; retain focus outlines and inline-prose link cues. |
| P2 | No cross-site UI inventory in CI | Add route checks for icons, accessible names, action styling, overflow and accessibility; add docs/dev/MCP checks to CI. Separate test artifact directories prevent concurrent suites deleting one another's traces. |

## Verification scope

Main app inventory: `/`, `/developers`, `/reports`, `/reports/demo-recorded`, `/scan`, `/hosts`, `/repairs`, `/team`, `/usage`, `/batches`, `/security-overview`, `/sign-in`, `/privacy`, `/security`, `/shared` and the not-found view. API calls are mocked as signed out for this inventory; the existing browser suite separately exercises authenticated batch, report, team, usage, repository, approval and failure states with synthetic data.

Platform inventory: all 13 documentation routes derived from committed MDX files, both developer pages, and the MCP landing page. Status data is mocked and no playground scan is submitted. In total, 32 route/view cases at 1440px and 390px. Existing responsive and theme suites add 360/768/1024px and light/dark checks. Viewport emulation is not physical-device testing.

No missing native-button SVGs, unnamed buttons, underlined native buttons, horizontal document overflow or axe violations in the tested inventory. Native browser controls (file picker, select menu) retain platform rendering. Disclosure triangles and chart state markers retain their semantic purpose; icons do not replace labels.

Builds: main app, docs, developers and MCP. Local unit suite: 364 passing tests. Browser and platform suite outputs are saved privately with screenshots. Automated checks are not a claim of complete WCAG compliance, real-user usability testing, all possible application states or end-to-end live repair success.

## Brand consistency verification

Expanded the inventory to both light and dark themes at 1440px and 390px: 32 route/view cases × 4 combinations, plus all five populated security-dashboard tabs × 4 combinations (148 rendered checks). The dashboard cases use explicitly synthetic report data, not production activity.

Each case checks the rendered ShipTested mark and text, at least a 24px mark, a fully visible brand within the initial viewport, and at least 4.5:1 foreground/background contrast. The helper resolves modern CSS colours with canvas and composites transparent backgrounds; treating Tailwind's `oklab` values as RGB would produce false failures. The checks cover settled theme rendering; they are not a guarantee about every animation frame or every possible stored browser state.

The brand uses the same boat/brackets/check symbol, ShipTested spelling, shared local font families and theme-aware foreground/accent system across the app, docs, developer site and MCP landing page. Reading pages keep a documentation layout; operational dashboards keep task-oriented navigation.

The populated repository table exposed a mobile document-overflow bug from off-screen accessibility labels. Its scroll region now establishes a positioning context. Chart legend columns now explicitly accommodate action icons, state swatches, text and numeric values; static rows no longer show misleading filter icons. The fixes preserve data, actions and access gates.

This verification records the local implementation. It does not claim these latest changes are live on production domains.
