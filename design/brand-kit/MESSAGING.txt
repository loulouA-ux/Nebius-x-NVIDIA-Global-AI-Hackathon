SHIPCHECK / MESSAGE SYSTEM
Scan. Check. Ship.
Code security, backed by evidence.

Voice: direct, calm, specific. State the observation, its scope and next action. Avoid false certainty, fear-based copy and vague AI claims.

Landing headline: Find the issue. Inspect the fix. See the evidence.
Landing description: Investigate code-security findings, test supported fixes in isolation and review the evidence before opening a pull request.
Primary CTA: Connect repository
Secondary CTA: See the workflow

Social messages:
1. Scan. Check. Ship. Code security, backed by evidence.
2. A proposed fix is a starting point. The diff, tests and evidence make it reviewable.
3. Human review stays in the loop. Inspect the patch before it becomes a draft pull request.

Transactional email template:
Subject: ShipCheck: results ready for {repository}
Your scan of {branch} completed at {timestamp}. Review {findingCount} findings and the check coverage in ShipCheck.
CTA: Review scan
Send only after a verified completion event. Never include secrets or raw logs in email.
